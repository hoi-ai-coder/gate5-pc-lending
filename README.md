### 環境
- Python 3.x
- Flask 3.x

pip install -r requirements.txt

ブラウザで `http://127.0.0.1:5000/` を開く。

## 4. 実装上のポイント

### 二重貸出防止
貸出確定時に `UPDATE devices ... WHERE status='AVAILABLE'` を実行し、更新件数が1件の場合だけ処理を続行する。2人が同時に同じ端末を確定しても、先に状態変更できた1件だけが成功する。

### トランザクション
貸出では「devices.status更新」と「lendings登録」、返却では「lendings.returned_at更新」と「devices.status更新」を同一トランザクションで実行する。途中で失敗した場合はROLLBACKする。

### 二重送信
貸出申請ごとに `request_token` を発行し、lendings側にUNIQUE制約を設定する。同一トークンの再利用は拒否する。

## 6. 振り返り

### 6-1. 8観点について
8観点すべてについて仕様を整理した。再提出時には、本人が8観点を一つずつ確認し直し、本人回答を別ファイルに記録した。

### 6-2. 言われれば当たり前だったのに気づきにくかった項目
1. 2人が同時に同じ端末を貸し出すケース：一人で順番に操作する前提で考えていたため。
2. 複数テーブル更新の途中で処理が失敗するケース：処理が最後まで成功する前提で考えていたため。
3. ブラウザバックから再度確定するケース：画面上の通常導線だけを前提に考えていたため。

### 6-3. Gate1から増えた観点
入力値や通常の状態遷移だけでなく、同時実行、二重送信、処理途中の失敗を要件定義段階で確認する観点が増えた。今後は「同時に操作されたら」「同じ操作が複数回行われたら」「途中で失敗したら」を確認する。
